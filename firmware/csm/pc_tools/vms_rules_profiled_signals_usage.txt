실행 순서

1. 입력과 생성물 위치
   - generator/profile: firmware/csm/pc_tools/
   - input: reference/vehicle-db/HYM_HAMT2.0_CAN DB_R13_260206.xlsx
   - output: generated/can-db/

2. 가장 쉬운 방법
   - run_vms_rules_build_example.bat 를 더블클릭

3. 직접 명령어로 실행하고 싶으면
   py firmware/csm/pc_tools/vms_rules_from_excel_profiled_signals.py --excel "reference/vehicle-db/HYM_HAMT2.0_CAN DB_R13_260206.xlsx" --profile "firmware/csm/pc_tools/profile_hamt_like_r13.json" --outdir "generated/can-db" --only ALL --system-bus 0 --driving-bus 1 --prefix vms_rules --suffix R13

4. 결과물
   generated\can-db\vms_rules_SYSTEM_R13.json
   generated\can-db\vms_rules_DRIVING_R13.json
   generated\can-db\vms_rules_MERGED_R13.json

설명

- 기존 Qt는 top-level 시간 규칙만 읽는다.
- 이 생성기는 기존 필드를 그대로 유지하면서, 각 rule 안에 signals 배열을 추가로 넣는다.
- 그래서 지금 Qt와도 충돌 없이 공존 가능하다.
- 나중에 Qt를 확장하면 signals를 이용해 값 범위, 비트 플래그, enum 검사까지 붙일 수 있다.

주의

- merged 파일은 SYSTEM/DRIVING에서 같은 ID가 있을 수 있으니 bus를 분리해서 만드는 편이 안전하다.
- bat 예시는 system=0, driving=1 로 넣었다.
