# Service/HIL observation contract — P1 format / P2 CSM hooks

Authority: L2 DEBUG OBSERVATION FORMAT. Existing REV.B/network/wire contracts own
all product behavior; this contract does not grant control permission.

## One definition and execution entry

- `contract.json` owns diagnostic event IDs, typed fields, producers, clock domains,
  relations and profile. `generated/manifest.json` owns the generated byte offsets,
  lengths and hashes. Do not hand-copy field offsets into consumers.
- Generate with `python firmware/csm/tools/generate_observability.py` from the CSM
  root. Verify with `--check --android-root <resolved-APP-root>`.
- `generated/Observation.h`, `CanonicalObservation.kt`, `observation.py` provide
  the same typed encode/decode contract. C++ uses caller storage; Kotlin/Python
  decoder objects are not an allocation-free producer API. P2/P3 must put primitive
  snapshots behind bounded debug-only producer calls, not allocate events in hot paths.
  Generated Kotlin Writer now provides preallocated primitive producer methods.
- APP's existing `GenerateCanonicalProtocolTask` verifies schema and generated
  Kotlin hashes, then copies the canonical output into its build-generated sources.
  APP does not own another layout or require Python at runtime/build time.
- Each repo's `tools/observability/bindings.json` owns source anchors/scenario
  references, not layouts. Anchor checks prove location only. CSM P2 hook/proof
  scopes are recorded there; APP actual owner hooks and remaining gaps are recorded separately. Existing summaries are
  references, not high-rate coverage. No binding grants runtime coverage.

`schema_sha256` is SHA256 of sorted-key, compact, ASCII-escaped canonical JSON,
including relation definitions. Generated file hashes are separate. Bindings,
source/artifact identity and test scenarios are separately hashed in evidence;
moving an owner file alone does not change the wire hash. The full digest is carried
in every debug envelope; mismatched/unknown schemas fail decoding, never downgrade.

## Framing and identity

The generated manifest is the exact layout reference. Observation record 30 uses
the current TypedFrame outer framing (11-byte overhead, 512-byte payload limit),
but **not** its canonical publication sequence. Its fixed 72-byte payload envelope
contains version, producer, clock, reserved zero, LE endian tag, trace sequence,
existing 64-bit epoch/boot identity, raw ticks, event ID/body length and full schema hash.
The remaining bytes are one typed event. No fragmentation, native struct packing,
transport queue, replay or new control heartbeat is defined here.

Current event frame lengths are calculated by `83 + manifest.events[].body_bytes`;
the largest is DatagramBytes at 227 bytes, below the existing TypedFrame maximum.
Its 128-byte bounded array matches `WifiRealtimeMailbox::kRealtimeDatagramCapacity`.
Current valid state/proof frames are 75/47 bytes (`TypedRecords.h` plus framing).
`wire_length` is the observed receive/send length; `captured_length` is the actual
copied prefix, at most 128. Producers zero unused bytes. A shorter capture is
explicitly incomplete, not a full-payload comparison. Never read beyond received
storage, serialize credentials, or treat unvalidated raw IDs as accepted authority.
Codecs validate format, not the product meaning of arbitrary payload bytes.

IntentState (event11) links full semantic revision to selected generation and exact
three-lane bytes without changing control wire. BEGIN carries UI values, with
generation/data unavailable. STAGED/REJECTED carries selected image; SNAPSHOT is
initial/safe image with no invented user revision. Zero padding is not neutral.
The old Intent event remains decodable but is not the current Controller hook.

Trace sequence is unsigned 32-bit per producer recording session, advanced for
each attempted observation, including failed publication. The outer u16 sequence
is only its low 16 bits; it is not a loss counter. Readers use the full u32 value,
modulo wrap, and separate producer/run identity. Delta zero is duplicate; forward
delta greater than one exposes loss; half-range ambiguity or a missing recording
restart/identity is INCOMPLETE, not an inferred wrap/reset. Loss counters/ranges
must remain visible after buffer-full; failed loss reporting cannot imply PASS.

Existing network epoch, M7 boot, authority epoch, source epoch, activation epoch,
command/transaction ID, state generation, realtime wire sequence, proof reference
and mailbox token retain their current meanings. They are not interchangeable.
The envelope epoch and Resource owner_epoch/resource_id preserve all 64 bits of
Android Long identities; M7 u32 epochs are zero-extended. They are never narrowed
to the control-wire u32 identity domain. Zero is unknown/not applicable where no actual identity exists. A locally allocated
operation ID correlates syscall begin/end only; it is not another control identity.
Consumers join `(run, producer, existing epoch, operation)` for local operations
and existing wire identities/raw bytes for cross-device edges. APP capture/run
identity distinguishes APP restart; do not pretend M7 boot identifies APP restart.

Clock IDs distinguish M7 raw modulo-u32 milliseconds (zero-extended in u64),
Android elapsedRealtimeNanos and Android System.nanoTime. Convert units only after
decoding the declared domain. Do not subtract Android/M7/PCAN timestamps to claim
one-way latency without measured synchronization bounds. M7 wrap deltas are valid
only inside an unambiguous local interval. A reboot starts another boot/run domain.
No safety/freshness threshold is set by this diagnostic clock contract.

Stage 0 and unmapped reason/status/resource values mean UNKNOWN for evaluation;
typed integers are preserved, not forced to known-success enums. `result` retains
the native signed socket result or the referenced owner's result, as selected by
event/producer/stage. Syscall completion is not peer receipt or product acceptance.
`Admission.valid_fields` identifies available fields using the canonical
`admission_valid_fields` map (also generated as named constants); reserved bits are
zero. A field without valid source evidence cannot join an edge. Stage, clock and
producer constants are generated too. Implementation and actual execution coverage
are distinct, never inferred from declarations or source marker presence.

## Independent drain; low-rate existing evidence remains

Record 27 is currently schema 2 / 496 bytes / at most 1 Hz, or 507 wire B/s, per
`TypedRecords.h`, `emit_control_path_diagnostic` and `ProductUplinkEnvelope.h`.
It remains a summary. Existing `ControlPathFirstFailure` is a boot-only first
failure latch; DISARM/reconnect do not reset it. Match its boot/time to the run;
do not relabel a previous run's failure as the current first failure.

`CanonicalPublisher::publish` increments `publish_seq_next_` after any sink accepts
and fans one frame to USB/Wi-Fi. Sending USB-only debug through it would consume
canonical sequence unseen by TCP3333. P2 does not use that entry for debug data.
`UsbCdcSink::offer` currently uses PublishedFrameView and canonical sequence
accounting, so simply calling offer with a fake publish sequence is also wrong.
Use the existing sole USB writer with separate debug framing/accounting; do not
interleave bytes into a partially sent canonical frame. P2 implements that separation.
P4 must demultiplex debug records before canonical continuity accounting. Existing
live capture tools are not yet qualified for mixed debug streams. TCP3333/3334/UDP3335 keep
their existing roles and bytes; no M4 shared-memory field changes are needed.

## Capacity feasibility — static facts, not throughput qualification

| Source fact | Consequence |
|---|---|
| HostRealtimePlane period 20 ms, no catch-up | Normal state release at most 50/s; not a bound on UI events, hostile UDP or TCP traffic |
| WifiRealtimeWorker at most 4 receives/turn; signal-driven wakes | Bounded turn work; 5 ms fallback is NOT a bound on turns/s |
| ProductUplinkEnvelope 496 records/s, 109556 wire B/s | Existing declared product envelope, not measured USB throughput |
| Existing record 27 adds 507 B/s | Count separately from high-rate observation |
| UsbCdcSink queue 208 records / 40960 B, staging 512 B | Existing storage, not free space allocated to debug |
| main config: 2 writes / 1024 B / 1000 us per pump | Work caps; no guaranteed pump interval or drain rate follows |
| BOARD_USB_TRANSIENT_COVERAGE_MS = 0 | Does not prove any nonzero worst drain-gap coverage |

For each selected scenario compute `sum(event_rate * (83 + body_bytes))` separately
for CSM USB and APP local file, including begin/end, replacements, failures and raw
payload events. For illustration only, ONE Io + ONE Bytes event at nominal 50/s is
`(120 + 227) * 50 = 17350 B/s`. This is not the full trace, maximum ingress, or a
capacity PASS. Transaction, telemetry and extra proof/admission stages add load.
Ring requirement is `maximum producer byte rate * bounded drain gap + burst`,
plus fixed indexing/loss overhead. Max inbound rate, burst, worst drain gap and
sustainable simultaneous USB/local-file throughput are **UNRESOLVED**. No arbitrary
ring size, sampling, queue expansion or numeric recovery threshold is approved here.

P2/P3 must choose finite storage within the real memory/profile budget, count
overflow/contention without blocking control, and provide deterministic overflow
tests. P6 measures enabled service gap/CPU/high-water/loss/cadence under the exact
artifact. Unproved bandwidth/lost required events makes evidence INCOMPLETE, not a
runtime permission gate. Off-build stripping and ON/OFF noninterference remain
P2/P3/P5 proofs; compiling an unused codec alone does not establish them.

## P2 actual owner implementation / removal boundary

`include/board/observability/DebugObservation.h`, `CSM_OBS(...)`, and
`OBS_BOUNDARY:<binding>` identify DEBUG_TRACE only. The existing
`BOARD_ENABLE_SERVICE_HIL_OBSERVABILITY` flag removes the storage, event calls,
argument evaluation and worker byte/operation counters when zero. Do not remove
record27, existing first-failure or product evidence/policy along with debug trace.

USB debug writes participate in physical attempt/zero/partial/backpressure counters
and the existing USB stall closure. Debug bytes do not increment canonical frame or
publish-sequence success. Debug-only short-write transitions do not generate one
canonical BOARD_EVENT per attempt. Disconnect/stall discards an unfinished debug
frame with explicit usb_aborted evidence; no additional timeout or control gate exists.
No M4, FDCAN, pinned stack, IPC, control wire, retry or threshold changes occur.

Three fixed SPSC rings (32 primitive slots each) are written solely by existing
M7 foreground / realtime worker / socket worker contexts (producers 1/2/3).
No heap, formatted strings, CRC, blocking IO, spin/CAS retry or new thread occurs
at producer hooks. A slot contains the existing Meta and at most 144 body bytes;
`sizeof(State) < 24576` is a compile-time storage ceiling, **not** a throughput
qualification. u32 indices use acquire/release and are required always lock-free.
The foreground sole USB writer performs generated framing/CRC. It starts debug
only with an empty canonical queue; an already partial debug frame completes
before subsequent canonical bytes. Existing write/byte/time budgets apply to both;
debug never enters RecordAdmission, canonical sequence assignment or sink offer.
This bounds work/storage, not worst service time: sustained canonical load can
starve debug and produce INCOMPLETE evidence. Hardware overhead remains unmeasured.

Sequence advances on every attempted event, including loss reports. Overflow
keeps cumulative modulo-u32 drop/high-water counters and producer-owned first/last
missing sequence; next successful producer opportunity emits TraceLoss(reason=1,
ring full). If a producer stops while full, its range waits for its next event;
foreground Capacity still exposes cumulative loss when USB can drain. A stream
ending before loss/range recovery is INCOMPLETE. Never infer zero loss from silence.
Existing 1Hz record27 call site emits Capacity resources 100/101/102 (rings 1/2/3),
104 (USB partial debug frames aborted); service_gap_ticks=0 is **unmeasured**, not
zero scheduling latency. Record27 payload/rate and boot-only first-failure remain
unchanged. Disconnect never replays a debug partial suffix on another USB epoch.

P3/P4 correlation rules:

- UDP Io: stages 1/2 syscall begin/result; stage 3/7 actual mailbox publish result.
  Receive token is unavailable before publish. Join operation to its staged token,
  then Admission/Proof by boot + token + raw validated wire identity. Raw capture
  is untrusted, bounded and zero-padded. Io wire identity fields zero are unavailable,
  not real zero-valued accepted IDs. TX Io has the selected proof rx_token.
- Admission: mailbox stages 3/4/5=stage/replace/take; rejected reason 1=RX busy,
  2=proof-stage busy. main decode rejection has token-only valid_fields; authority
  acceptance/rejection has valid_fields=31 and raw HostRealtimeAdmission result;
  subsequent stage 8 (or 7 rejection) is raw HostStateAdmission outcome. Interpret
  those enum domains at their ordered source boundary, not as global reason IDs.
  Main envelope epoch=0 is unavailable; join boot/token, never invent a network epoch.
  USB drain order is not a cross-thread total order: a mailbox consumer can run
  between publication unlock and the producer's trace call. Per-producer sequence
  and token/wire causal joins are authoritative; equal millisecond ticks or drain
  order alone cannot determine which CPU boundary happened first.
- Proof: stages 3/4=stage/replace, 5=selected, 9=discarded by existing open-floor/peer
  rule. Actual sent length/result is Io completion; full syscall acceptance is not
  Android receipt. Existing proof and ACK counters remain the summary truth.
- TCP Stream: channel 3333/3334; stages 1/2 are syscall begin/result, signed native
  result plus connection-local byte offset. Reconnect resets only diagnostic byte
  offsets; full boot/connection identity remains separate from per-producer sequence.
  Publish stages 6/7 carry full canonical sequence and each actual sink result;
  sink index 0 (USB) / 1 (3333) is the canonical publisher's existing installation.
  A socket chunk may contain partial/multiple frames: do not claim frame delivery
  from chunk count. Matched begin/end plus native positive byte ranges bound progress.
- Transaction dispatch stage 5 is framed RX, **not** handler acceptance; ACK stage 3
  holds actual payload status/reason, 6/7=ACK mailbox admission/rejection. ACK rejection
  reason 1=invalid/inactive, 2=full, 3=encode failure, 4=generation changed. Worker
  stage 2 is complete socket acceptance, stage 5 is nonterminal result. Command and
  N-shot transaction IDs remain distinct. Handler application through the real main
  frame parser has target compile, not focused runtime proof in this phase.
- Resource: stage 1/2 retains existing WifiWorkerCallPhase and signed result; no
  socket pointer or fabricated resource identity. Existing summary owns arena and
  first-failure truth. Source marker checks validate routing only, not runtime PASS.
